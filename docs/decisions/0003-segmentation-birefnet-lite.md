# 0003. Сегментация: BiRefNet-lite в ONNX

Дата: 2026-10-28. Статус: принято (этап 2).

## Решение
- Модель — BiRefNet, веса general / swin-tiny (`BiRefNet-general-bb_swin_v1_tiny-epoch_232`), ONNX-экспорт из релизов rembg.
  Лицензии репозиториев: BiRefNet — MIT, rembg — MIT; это не полная проверка цепочки прав конкретного ONNX-артефакта. Файл 224 МБ, `models/birefnet-lite.onnx` (не в git), sha256 в `scripts/fetch_models.py`. Актуальные границы — `../../THIRD_PARTY_NOTICES.md`.
- ONNX Runtime (MIT), только CPU, вход 1024×1024.
- Замер (12 ядер, Windows): ~5 с на фото + ~4 с на загрузку модели один раз.

## Почему не полная BiRefNet
Полная (swin-large) весит 970 МБ и на CPU работает в несколько раз дольше. На тестовых фото лёгкая даёт чистый край; если на этапе 3–4 края окажутся слабым местом, сравним.

## SAM 2 (запасной вариант)
Пока не подключён: на хороших фото BiRefNet хватает. Нужен, когда в кадре несколько объектов (стена с гитарами, ремень, кейс) — тогда подсказка точкой или рамкой.

## Последствия
- Модель качается отдельно: `uv run python scripts/fetch_models.py`.
- В текущий исходный релиз модели не включать. Возможное встраивание в Docker/бинарный релиз требует отдельного согласования происхождения весов и лицензий; старый вариант «вшить при сборке» не является разрешением на распространение.
