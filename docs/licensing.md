# GuitarTrace: лицензирование и самостоятельный релиз

Дата проверки: 2026-11-12. Это техническая инвентаризация, не юридическое заключение.

## Статус Apache-2.0

Собственный код GuitarTrace распространяется под Apache-2.0 по решению владельца проекта о публичном релизе. `LICENSE` содержит официальный текст без изменений; его приложение с `[yyyy] [name of copyright owner]` — часть официального образца, а не выдуманные реквизиты проекта. Имя пакета — `gbcv`, версия — из `pyproject.toml`. Имя правообладателя не выводится из Git-автора и не выдумывается.

В `pyproject.toml` указан SPDX `Apache-2.0`; LICENSE, сторонние уведомления и документы происхождения входят и в sdist, и в wheel. Лицензия распространяется на собственные Python/JS/CSS/HTML-исходники, scripts, tests, конфигурацию и документацию, но не заменяет лицензии отдельно устанавливаемых библиотек, весов, фотографий и результатов. Это не юридическая гарантия отсутствия любых прав третьих лиц.

## Что проверено и что исключено

`reference/guitar-blueprint.mjs` был импортирован из `design/prototypes/art/guitar-blueprint.mjs` проекта Guitar Archive (историческое ТЗ, первоначальный коммит `e795f99`). Собственной лицензии или подтверждения правообладателя у образца нет. Ни Python-сервис, ни CLI, ни редактор его не импортируют и не читают. Он удалён **только из текущего дерева** как ненужный исторический материал; история старого репозитория не изменялась.

Исторический `renderer/blueprint.mjs` (`2415b87`) содержит совпадающие фрагменты образца; сам renderer удалён ранее (`526b7be`). Старое интеграционное ТЗ и ADR 0001 в текущей документации заменены краткими историческими справками. Упоминание исходного проекта здесь — фиксация происхождения, не бренд, зависимость или предложение интеграции.

### Закрытие вопроса spline_samples

Бывшая **`src/gbcv/contour.py::spline_samples`** в `74d21f6` сопровождалась комментарием о соответствии `renderer/blueprint.mjs`. Поэтому она не объявлялась независимой или собственной лишь на основании авторства коммита.

Повторная проверка вызовов в src, scripts и tests подтвердила: `spline_samples` вызывалась только из `_fit`, `_fit` — только из `fit`, а `fit` — только из трёх старых unit-тестов. Приложение и диагностические скрипты эту цепочку не использовали. По прямому поручению владельца вся цепочка `spline_samples`/`_fit`/`fit` и ненужный импорт cKDTree удалены; тесты удалённого API заменены проверками действующей геометрии. Старый генератор не использовался для написания замены: замена не потребовалась.

Сохранились используемые `smooth`, `resample`, `dp_closed`, `_dp` и standalone `find_corners`. Экспортирующий `trace.curve_path` не изменён. SHA-256 SVG синтетической fixture во всех трёх стилях зафиксированы до удаления цепочки и проверяются unit-тестами. На трёх существующих прозрачных фото сравниваются SVG силуэта и растровое наложение до/после без ML (`scripts/check_release_geometry.py`); материалы остаются только в игнорируемом `out/release-geometry/` и не распространяются.

Таким образом, конкретный выявленный фрагмент с неподтверждёнными правами отсутствует в текущем публикуемом дереве; это не ретроактивное перелицензирование старой истории.

### Остальные исходники

История показывает развитие оставшихся исходников внутри этого репозитория; при предыдущем аудите импортов, заголовков, URL и исторических вводящих коммитов других конкретных импортированных реализаций не выявлено. Лицензия собственного кода применяется по поручению владельца проекта, а не на основании предположения, что Git-автор автоматически владеет чужим кодом. Сторонний SAM не скопирован в src и сохраняет upstream-лицензии; подробнее `sam2-provenance.md` и THIRD_PARTY_NOTICES.

`trace.py::_st`, `_path` и `curve_path` используют обычные SVG-атрибуты и стандартные математические операции. Само сходство короткого SVG-синтаксиса или формул не установлено как отдельное охраняемое заимствование. Код редактора не импортирует исторический генератор; API SAM используется через отдельную библиотеку, не через скопированное демо Meta.

## Новый GitHub-репозиторий без старой истории

Это подходящий способ не распространять удалённый образец и старый renderer, **но не способ обнулить права на оставшийся код**. Старый GitLab, remote origin и `.git` оставить без изменений. Не делать orphan/reset/filter-repo в старом репозитории и не использовать mirror push.

Подготовить отдельную пустую папку из проверенного коммита, а не копировать весь рабочий каталог. Включать только исходники, тесты, scripts, docs, eval CSV/README, `.github`, необходимые конфиги, README/LICENSE/уведомления, lock и launcher. Перед переносом просмотреть список файлов и секреты. Исключить `.git`, `.venv`, `.idea`, `.env` (кроме `.env.example`), models, samples, out, reference, dist, build, кэши, архивы и любые фото/веса/результаты вне этих папок. `.gitignore` сам по себе не защищает от копирования или уже отслеживаемых файлов.

В новой папке после отдельного разрешения можно создать независимый Git-репозиторий с одним начальным коммитом проверенного состояния. Не переносить старые refs/tags/remotes. На этапе подготовки разрешён один локальный коммит в исходном репозитории; создание второго Git-репозитория, push и публикация не выполняются. Точные команды переноса — `github-release.md`.

### Ограничения исходного релиза

Сохранять THIRD_PARTY_NOTICES и установку по lock. MPL/LGPL уже присутствуют в зависимостях; завершающий этап не добавляет и не меняет их. Они не означают автоматическое перелицензирование собственного кода. Это исходный релиз без сторонних бинарных библиотек/весов/фото, не готовый compliance-пакет для Docker/EXE/набора wheels зависимостей. Для такого распространения отдельно выполнить обязанности MPL/LGPL и проверить цепочку прав ONNX-весов. Отсутствие персонального copyright-уведомления не заменяется вымышленным именем.
