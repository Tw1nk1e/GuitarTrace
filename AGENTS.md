# GuitarTrace

Самостоятельное приложение: фото гитары → обводка SVG/PNG с ручным редактированием в браузере.
Обводим силуэт, накладку с ладами и фурнитуру; фото даёт пропорции. Ни мм-чертежа, ни JSON, ни шаблонов
семейств — это вырезано (`docs/decisions/0004-png-only.md`). Актуальные решения: `docs/decisions/0004-png-only.md`,
этапы: `PLAN.md`. `docs/brief.md` — историческое ТЗ, не источник актуальной архитектуры.

## Как работаем

- Отвечать человеку на русском.
- Один этап из `PLAN.md` за раз. Следующий — только после одобрения человека.
- Результат этапа показывать файлами в `out/` (SVG + наложение на фото), а не словами.
- Экономить токены: узкие задачи, без лишних прогонов, коммитить часто.
- Коммиты: без `Co-Authored-By` и упоминаний ассистента. Не пушить без просьбы.
- Перед push и разрушительными Git-операциями запрашивать подтверждение. Не откатывать чужие изменения.
- Спросить человека, если решение влияет на лицензию, хранение фото или набор/разметку фото.

## Жёсткие ограничения

- Только бесплатные открытые модели/библиотеки, без платных API.
- Для новых прямых зависимостей предпочитать MIT / Apache 2.0 / BSD и похожие разрешающие лицензии. Potrace (GPL) и Ultralytics YOLO (AGPL) не добавлять.
- Текущий стек НЕ исключительно разрешающий: tqdm содержит MPL-2.0, OpenCV wheels — FFmpeg под LGPL-2.1; бинарные научные библиотеки могут включать GCC runtime с исключением. Это не перелицензирует код приложения автоматически. Новые лицензионные исключения и распространение бинарных сборок согласовывать; см. `THIRD_PARTY_NOTICES.md`.
- Только CPU, обычный VPS. Цель — до 5–10 с на фото.
- Приватность: оригиналы фото не хранить дольше обработки, не писать в логи, в отладочных картинках — только маска гитары (людей не выводить), EXIF в выход не попадает.
- Вход недоверенный: проверка типа и размера файла, лимит пикселей (декомпрессионная бомба) — см. `src/gbcv/imageio.py`.
- Секреты только через `.env` (пример — `.env.example`).

## Окружение

- Windows 11, Git Bash / PowerShell. `python` в PATH — заглушка Store, не использовать. Всё через `uv`:
  - `uv sync` — зависимости; `uv run pytest` — тесты (модель не нужна).
  - `uv run python scripts/fetch_models.py` — веса BiRefNet в `models/`; `uv run python scripts/fetch_samples.py` — фото из `eval/samples.csv` в `samples/`.
  - `uv run python -m gbcv.server [--open]` — сервис обводки в браузере: http://127.0.0.1:8000 (фото только в памяти сеанса, 30 мин). Для человека — двойной клик по `Запуск.cmd` (модели при первом запуске, сам открывает браузер).
  - `uv run python trace.py samples/dl/*.webp` — обводка из терминала → `out/<имя>/trace.svg` + `out/trace.html`.
- Node не нужен: генератор SVG на JS удалён.

## Устройство

- `src/gbcv/` — конвейер на Python: `imageio.py` (безопасная загрузка) → `segment.py` (фон) → `orient.py` (ось, поворот, чистка маски) → `split.py` (корпус / гриф / голова) → `frets.py` (лады) → `contour.py` (сглаживание) → `trace.py` (силуэт, лады, колки, детали SAM, SVG). Точка входа — `trace.trace()`.
- `trace.py` + `src/gbcv/server.py` — единственный путь. Модели: BiRefNet (MIT) — фон, SAM 2.1 (Apache 2.0) — детали.
- Исторический генератор-образец исключён из текущего дерева: приложение его не использует. Вопрос происхождения оставшихся фрагментов — `docs/licensing.md`.
- `samples/`, `out/`, `models/` — в `.gitignore`. В git — только `eval/` (список фото, лицензии).
- Отладочные картинки: фото показываем только внутри маски гитары.

## Система координат

- Холст — пиксели повёрнутого фото, голова справа. X вдоль гитары: от торца корпуса к голове. Y поперёк, Y < 0 — басовая сторона (сверху).
- «мм» в коде — условные единицы от номинального масштаба (длина силуэта ≈ 1000 мм): нужны для толщин линий и порогов сглаживания/SAM. В результат не выходят.

## Стиль SVG

- Линии `currentColor`, три толщины в `trace.STYLES` (`thin` / `comic` / `png`); для сайта — `png`, жирные, чтобы не пропадали при уменьшении.
- Текста в SVG нет.
